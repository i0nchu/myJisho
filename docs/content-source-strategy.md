# Kotoba 大量詞條內容策略

> 狀態：提案，尚未核准任何外部資料的發布。  
> 目標：讓數萬筆詞條可追溯、可更新、可抽樣審核，而不是逐筆手工建檔。

## 決策原則

- 每一筆外部資料保留來源、下載日期、版本、原始 ID、授權與轉換紀錄。
- 免費不代表無義務；資料進產品前必須通過授權相容性檢查。
- 自動生成只能產生候選內容與風險分數，不能將詞條標為人工審核通過。
- 對使用者明確區分「已審核學習詞條」與「來源標註的基礎詞條」。

## 候選資料來源與用途

| 來源 | 最適合用途 | 授權／限制 | 是否可取代繁中釋義 |
|---|---|---|---|
| JMdict、JMnedict、KANJIDIC2（EDRDG） | 詞形、讀音、詞性、義項結構、姓名、漢字資訊 | CC BY-SA 4.0；需署名、提供授權資訊，衍生內容須遵守 ShareAlike | 否；JMdict 公開配發的主要釋義並非繁中 |
| Tatoeba | 例句候選與翻譯對照 | 逐句授權與作者不同；文字預設 CC BY 2.0 FR，但不得假定音檔或每筆句子可商用／可改作 | 否；只能作例句來源 |
| 日語 Wiktionary／Kaikki 轉出資料 | 補充詞義、語源、標籤與交叉參照 | CC BY-SA + GFDL；結構與品質不均，需保留來源與再發布義務 | 部分、不可當唯一可靠來源 |
| SudachiDict | 斷詞、詞形正規化、讀音與搜尋 | Apache-2.0；不是使用者辭典釋義 | 否 |

外部商業辭典、網站或未明示可再利用的 API 不可抓取或複製。若需要完整且一致的日中釋義，候選路徑是取得出版社授權，或編寫並持有我們自己的繁中學習內容。

## 建議的內容工廠

1. **原始層**：下載鎖定版本的來源檔，寫入不可變的來源清單與雜湊；不直接人工改檔。
2. **正規化層**：以可重跑的轉換器產生 Kotoba canonical JSON；保留原始 ID 與來源欄位。
3. **自動品質閘門**：Schema、讀音/Kana、詞形重複、關聯目標、授權、例句逐筆授權、敏感詞與大幅差異檢查全數執行。
4. **風險分流**：依高頻、初學者詞、同音易混、醫療／法律／成人敏感內容、來源缺漏、機器生成痕跡與驗證失敗提高風險。
5. **人工審核**：只處理高風險與高流量詞；每個低風險批次以固定抽樣比例加上風險加權抽樣驗收。若錯誤率超標，整批退回，不逐筆硬修。
6. **分級發佈**：
   - `featured`／`curated`：人工審核，提供完整學習解說。
   - `imported`：只在產品政策明確允許時，標示來源與未編輯狀態；不得偽裝成已人工驗證。
   - 高風險或授權不清的資料：一律不上線。
7. **可回滾發布**：以資料批次、版本與 manifest 發布；出現授權或品質問題可撤回單一批次。

## MVP 後的第一個批次

- 先以 JMdict／KANJIDIC2 建立可重跑的詞條骨架，再以 SudachiDict 充實搜尋與詞形處理。
- 例句僅匯入已逐筆確認可用的 Tatoeba 文字；第一階段不匯入外部音檔。
- 先精編並人工驗收高頻學習核心詞，再決定是否允許帶來源標示的長尾 `imported` 詞條進入公開 Beta。
- 在任何長尾公開前，完成授權清單、產品內 Attribution 畫面、逐詞條 provenance，以及獨立法務確認。

## 驗收標準

- 100% 匯入記錄有來源 ID、版本、雜湊與授權欄位。
- 100% 例句與媒體記錄保留其個別授權與署名需求。
- 0 筆未知／不相容授權資料可進發布 manifest。
- 0 筆未審核內容被標示為 `curated` 或 `featured`。
- 每批產出可由同一來源版本重建，並能在不影響其他批次下回滾。
