# Kotoba 產品規格（MVP）

- 文件狀態：Baseline for MVP
- 專案代號：Kotoba
- 適用里程碑：M0–M4
- 主要平台：iOS、Windows、macOS
- 範圍決策：Android 已依客戶指示移除（見 ADR-0005）
- 產品承諾：離線優先、無廣告、免帳號，以簡單日文協助學習者在數秒內理解詞義與用法

## 1. 問題、受眾與成功定義

### 1.1 要解決的問題

現有辭典常要求精確輸入、回應慢或一次呈現過多艱澀內容。Kotoba 的工作不是最大化收錄量，而是縮短「看到陌生詞」到「知道最常見意思、看懂例句並能聽到發音」的時間。

### 1.2 主要受眾

- 已掌握平假名、片假名，程度約 JLPT N5–N2 的學習者。
- 希望直接以日文理解日文，手機快速查詞、桌面閱讀或寫作的使用者。
- 次要受眾為教師、高階學習者與快速確認用法者。

第一版不針對專業語言學、古典日文、完整語源或法律／專業翻譯需求最佳化。

### 1.3 北極星任務

使用者在沒有網路、沒有帳號的情況下，能以表記、讀音、活用形或羅馬字找到詞條，先理解主要義項和例句，再按需聽發音或查看相似詞差異。

### 1.4 MVP 成功指標

MVP 驗收以可重現測試為準，不以下載量或主觀「看起來完成」為準：

| 指標 | MVP 門檻 | 測量方式 |
|---|---:|---|
| 冷啟動至搜尋欄可輸入 | 一般目標裝置 P95 ≤ 2 秒 | release build，自動化啟動量測 |
| 輸入完成至首批結果 | P95 ≤ 150 ms | UI 整合效能測試，排除輸入法組字期間 |
| SQLite 搜尋 | 100k 模擬詞條 P95 < 100 ms | 固定硬體／資料集 benchmark |
| 搜尋黃金集 | 全部必測案例通過 | 100 常見詞、50 動詞、20 形容詞、20 片假名、20 羅馬字、20 歧義、20 負例 |
| 離線核心流程 | 100% 通過 | 關閉網路執行 E2E |
| 內容完整性 | 20 個精選詞條皆有主要義項、例句、來源／授權 | 發布 validator |
| 更新安全 | 下載中斷、雜湊錯誤、替換失敗均保留舊版 | fault-injection 整合測試 |
| 個人資料保留 | 重啟與辭典更新後收藏／歷史不遺失 | 跨啟動與更新 E2E |
| 平台 | 3 個主要平台皆可建置；至少 1 行動＋1 桌面實機 smoke test | CI artifact + 測試紀錄 |

MVP 不宣稱已驗證市場契合；公開試用後另量測首查成功率、無結果率、首次正確結果點擊率與任務完成時間。

## 2. MVP 範圍

### 2.1 P0 使用者能力

1. App 開啟後搜尋欄自動取得焦點，不登入即可查詢。
2. 以漢字、平假名、片假名、常見 Hepburn 羅馬字查詢。
3. 以常見動詞與形容詞活用形查詢，結果明確標示為推測且可有多個候選。
4. 輸入時即時取得已排序候選；IME 尚在組字時不送出查詢。
5. 查看詞條的表記、讀音、合成音聲標示、主要詞性、主要義項、1–2 個例句及相似詞差異。
6. 展開其他義項、使用注意、搭配、活用、圖片、音訊及來源等次要內容。
7. 以系統日文 TTS 播放詞彙；若存在本地音訊，可播放且清楚區分合成／真人。
8. 收藏、取消收藏、查看收藏與搜尋歷史；重啟後保留。
9. 使用深色模式、字體大小設定及無障礙技術。
10. 桌面以雙欄操作並支援 `/`／`Ctrl+L`、方向鍵、Enter、Esc、平台等價收藏鍵與不干擾文字輸入的 Space 發音。
11. 查看已下載的圖片與音訊；沒有媒體時不顯示空殼區塊。
12. 在明確動作下檢查並安裝完整辭典資料包更新，失敗時仍可使用舊版。

### 2.2 P0 內部能力

- 可從版本控制中的 canonical data 與 editorial overlay 重建 SQLite 與 release artifacts。
- 內容編輯器支援單一管理者完成詞條、義項、例句、關係、媒體、中繼資料、狀態與預覽編輯。
- 所有人工與外部內容具來源、授權、審核和修改記錄；AI 草稿不可直接發布。
- CI 執行格式、分析、單元、schema、資料、黃金、Flutter、編輯器及至少一種平台 build 驗證。
- 至少 20 個「完整精選」示範詞條，而非未審核匯入資料偽裝的內容量。

### 2.3 明確非目標

MVP 不實作：AI 對話／教師、中文詞義、單字卡、間隔重複、測驗、OCR、手寫辨識、相機翻譯、社群、公開投稿、廣告、訂閱、帳號、雲端同步、商業辭典抓取。

以下為 P1 候選，不得阻擋 MVP：拼字容錯／模糊搜尋、整句分詞、東京式音調、真人錄音擴充、相似詞比較專頁、差分更新、錯誤回報、分享選單、瀏覽器擴充、300–1,000 人工詞條。

## 3. 核心流程與體驗規則

### 3.1 快速查詞

1. 啟動後焦點位於搜尋欄。
2. 使用者輸入；80–150 ms debounce，IME composing 期間不查詢。
3. 每列顯示表記、讀音、主要詞性、一行定義、常用度與活用來源提示。
4. 方向鍵／觸控選擇；手機開啟詞條頁，桌面更新右欄。
5. Esc 先清除查詢，再執行返回；規則須在平台測試中固定。

空查詢顯示最近搜尋與收藏入口；無結果顯示可行提示但不捏造候選；資料庫不可用則顯示復原／重試，不清除個人資料。

### 3.2 詞條資訊層級

首屏依序為表記、讀音、發音、主要詞性、最常見定義、1–2 例句、相似詞差異。其他資訊預設收合或降低視覺權重。使用者放大字體時允許內容變高，不可截斷核心資訊。

### 3.3 離線與更新

查詢、詞條、例句、系統 TTS、收藏、歷史與已下載媒體不依賴網路。更新失敗是可復原狀態，不能讓現有辭典不可用。更新不得更動獨立的 user database。

### 3.4 內容信任

- 定義只使用日文，不設中文或英文翻譯欄位。
- 外部內容能追溯至來源與授權；圖片／音訊分別記錄授權。
- AI 參與的內容標為 `ai_draft`，必須經人工審核流程才可 `approved`／`published`。
- TTS 永遠標示「合成音声」，不可暗示真人錄音。

## 4. 可測量驗收條件

### AC-01 首次啟動

**Given** 乾淨安裝且裝置離線，**When** 使用者啟動 App，**Then** 不出現登入、廣告或網路阻擋，搜尋欄在 2 秒內可輸入且具有焦點。

### AC-02 輸入正規化

以下查詢的第一候選須符合固定 fixture：`食べる`→食べる（主要表記）、`たべる`→食べる（讀音）、`ガッコウ`→学校（正規化讀音）、`taberu`→食べる（羅馬字）、`shimbun`／`shinbun`→しんぶん候選。原始查詢保留用於提示與 debug。

### AC-03 活用還原

`食べました`、`食べられない`、`拾って`、`行かなかった` 能將預期原形放入前段候選；UI 顯示「由…的活用形推測」而非斷言唯一答案。固定的 50 動詞與 20 形容詞集全部通過。

### AC-04 排序可解釋

每個開發模式結果能輸出命中鍵、命中方式、原始分數、加權分數與活用分析。完全符合不得被較低層級模糊／包含結果覆蓋；相同輸入和資料版本的排序可重現。

### AC-05 詞條體驗

20 個精選詞條皆先顯示簡單日文主要定義和至少一個對應例句；次要內容可展開；無圖片／音訊時沒有破版或誤導性按鈕。

### AC-06 發音

點擊發音按鈕播放系統日文 TTS；按鈕具可理解的螢幕閱讀器標籤，畫面標示合成音聲。離線測試通過。

### AC-07 個人資料

收藏與歷史在 App 重啟後仍存在；更新或替換 dictionary database 後內容不變；可清除歷史且不影響收藏。

### AC-08 桌面與行動

手機主要流程不需橫向捲動；桌面寬版為結果／詞條雙欄。指定快捷鍵均有自動化或手動測試證據，且可停用；Space 在搜尋欄輸入時不得播放。

### AC-09 無障礙與外觀

淺／深色均達 WCAG 2.2 AA 文字對比目標；200% 文字尺度仍可操作；所有互動有語意標籤與鍵盤焦點；狀態不只依靠顏色；遵循 reduced motion。

### AC-10 更新安全

manifest 不相容、大小錯誤、SHA-256 錯誤、下載中斷、磁碟不足或替換失敗時，App 顯示明確錯誤並重開舊資料庫；成功更新後版本可驗證且個人資料保留。

### AC-11 可追溯發布

發布 validator 對重複 ID、缺表記／讀音／定義／來源／必要授權、斷裂 relation、不相容 schema 或不可開啟 SQLite 以非零狀態阻擋發布，並產生逐項報告。

### AC-12 平台發布候選

iOS、Windows、macOS CI build 均成功；至少各一個行動及桌面平台完成離線 smoke test。未實機驗證的平台不可標示「已驗收」。

## 5. UX 狀態矩陣

| 區域 | Loading | Empty | Error | Offline |
|---|---|---|---|---|
| 搜尋 | 保留輸入、非阻塞進度 | 最近搜尋／收藏 | 可重試，保留查詢 | 正常運作 |
| 詞條 | 骨架但保留選取 | 不應由有效結果進入 | 回到結果／重試 | 正常運作 |
| 媒體 | 個別資產進度 | 隱藏區塊 | 顯示替代內容 | 已下載可用，未下載不阻擋 |
| 更新 | 可取消下載 | 顯示目前已是最新版 | 明確原因及重試，舊版可用 | 顯示需連線，不影響查詞 |
| 收藏／歷史 | 本機快速載入 | 提供返回搜尋動作 | 不得影響辭典查詢 | 正常運作 |

## 6. 責任界面與產品治理

| 決策 | Accountable | Consulted／Required evidence |
|---|---|---|
| MVP 範圍與驗收 | PM／客戶 | UX、工程、QA |
| 資訊層級與互動 | Product／UX | Flutter、Accessibility、QA |
| 搜尋語意與排序 | Search owner | Product、Data、golden tests |
| 內容正確性／發布 | Editorial owner | 日文審核者、Licensing、validator |
| 資料與媒體授權 | Licensing owner | Legal review、provenance report |
| 架構／更新安全 | Architecture owner | Data、Flutter、Security、ADR |
| 發布品質 | QA／Release owner | 各 owner 的 CI 與驗收證據 |

任何人可以提議變更，但 P0 範圍、schema、搜尋排名契約、資料包格式或授權政策的變更必須有 ADR／變更紀錄及相應測試。資料正確性與授權安全優先於進度；MVP 不以未審核內容量換取表面完整。

## 7. MVP Gate

只有在所有 P0 acceptance criteria 有證據、核心 CI 全綠、無已知 Blocker／Critical 缺陷、20 個詞條發布檢查通過、三平台可建置且離線實機 smoke test 完成後，才可稱為 MVP。未完成的 P1 或內容擴充不影響此 Gate。
